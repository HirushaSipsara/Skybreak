SE3062 Intelligent Systems · Skybreak · Relay support companion

How Relay thinks, and the theory behind each part

Relay is the hovering support robot that follows Arc, heals him, shoots at threats and keeps itself out of trouble. This guide walks through every decision layer, the lecture theory it uses, the real numbers from the tests, and the questions an examiner is likely to ask.

Overview in one minute

Relay is a hybrid (subsumption) agent. Every 0.2 seconds it runs one decision cycle made of stacked layers, each a technique from the course:

LayerQuestion it answersTechniqueLecture
0 ReflexesIs there something I must do right now, no thinking?Prioritised condition-action rulesL03
1 World modelWhat is out there, including what I can no longer see?Internal state, transition model, confidence decayL02, L03
2 AssessmentHow urgent is healing, defending, saving myself?Mamdani fuzzy inference, centre of gravityL09
3 DecisionWhich action is best right now?Expected utility EU = P × UL03
4 PlanningHow do I get there safely?A* with an admissible, consistent heuristicL04, L05
5 PositioningWhere exactly should I stand?Simulated annealing (local search)L05

This is what makes Relay "go beyond a basic uninformed search", the assignment's core requirement: informed search, local search, fuzzy reasoning and utility theory working together, each one testable on its own.

Agent program Lecture 03

Architecture

Lecture 03 ends with the point that real systems mix architectures. Its example is a self-driving car: a utility engine plans the route, and a reflex layer handles the brakes. Relay works the same way, and each layer feeds the next.

flowchart TD
    S[Sensors: line of sight, health, positions] --> M[L1 World model: threat tracks, health trend]
    M --> R{L0 Reflex rule fires?}
    R -- yes --> A[Act]
    R -- no --> F[L2 Fuzzy: heal / defend / self urgency]
    F --> U[L3 Expected utility: argmax over actions]
    U --> P5[L5 Annealing: best spot]
    P5 --> P4[L4 Tactical A*: safest route]
    P4 --> A

function RELAY-AGENT(percept) returns action          // RelayBrain.SenseAndDecide
    model   ← UPDATE-MODEL(model, percept)           // L1 RelayPerception.Sense
    if a reflex rule matches then return its action  // L0 RelayReflexes (checked every frame)
    urgency ← FUZZY-ASSESS(model)                    // L2 RelayFuzzyModel.Assess
    action  ← argmax_a  P(success|a) × U(a)          // L3 RelayUtility.Score / Select
    if action needs a position:
        spot ← ANNEAL(objective for action)          // L5 RelayPositionSearch
        route ← A*(here, spot, cost = length + λ·exposure)   // L4 RelayTacticalGraph
    execute(action, route)
Layer 0 · RelayReflexes.cs Lecture 03 simple reflex agents

Reflexes: act without thinking

Theory. A simple reflex agent maps the current percept straight to an action with IF-THEN rules. It has no memory, so it is fast but blind to anything hidden. When rules can conflict you must give them a priority, which is the lecture's drone-obstacle question.

In Relay. Rules checked every frame, before any deliberation (subsumption: the first match wins):

  1. Relay's health is 0 → stay disabled.
  2. The player is down → stop and wait.
Say this honestly in the viva: a third rule, "evade the boss's slam zone", is designed but not implemented, because the boss does not publish where its slam lands and the boss code was deliberately not changed. Stepping out of the player's line of fire, first planned as a reflex, is handled by layers 5 and 3 (the Reposition action) instead.
Layer 1 · RelayPerception.cs Lecture 03 model-based agents

World model: remembering what it cannot see

Theory. A model-based agent keeps internal state about parts of the world it cannot currently see. To update that state it needs a transition model (how the world changes on its own) and a model of what its own actions do. This is the standard answer to partial observability.

In Relay. Every hostile it sees becomes a track: last position, velocity, time last seen. When a track goes out of sight:

predicted = lastPosition + velocity × Δt (capped at 4 m) ← transition model
confidence = e−Δt / 1.5 s (forgotten below 0.1, about 3.5 s)

Confidence is used later as a weight: an enemy seen 1.5 s ago counts as 0.37 of a threat. Layer 1 also records the player's health trend (health lost per second over the last 2 s) and whether the heal and shot are physically possible from where Relay is (range and line of sight).

Layer 2 · RelayFuzzyModel.cs + Algorithms/Fuzzy Lecture 09 parts 3–4

Fuzzy inference: how urgent is each need?

Why fuzzy. "Low health" and "near" are vague. The old code healed only when health fell below exactly 25%, so at 25.1% it did nothing and at 24.9% it healed. That is the crisp-logic failure the lecture describes. Fuzzy sets let a value belong partly to several sets, so urgency changes smoothly.

The pipeline (Mamdani, exactly as in the lecture)

  1. Fuzzification: a crisp input gets a membership degree μ ∈ [0,1] in each term. Triangle (a,b,c), trapezoid (a,b,c,d). Rising slope (x − start)/(peak − start), falling slope (end − x)/(end − start).
  2. Rules: IF-THEN with Zadeh operators: AND = min, OR = max, NOT = 1 − μ. Hedges: Very = μ², Slightly = √μ. All rules fire in parallel.
  3. Aggregation: for each output term keep the strongest rule (max), and clip that term's set at that height.
  4. Defuzzification: centre of gravity, COG = ∫ μ(x)·x dx / ∫ μ(x) dx.

The library is tested against the lecture's own worked examples: 18 °C is 0.4 Cold and 0.6 Optimal; Very gives 0.36 and Slightly 0.77; the hospital-robot rules give strengths 0.6 / 0.4 / 0.2 / 0.2; and the COG is 1690 / 41 = 41.22.

Worked example to practise by hand

Player at 50% health, health stable, boss 7.5 m from the player, Relay healthy.

  • PlayerHealth: Low = (0.7 − 0.5) / 0.25 = 0.8; Critical = 0; Healthy = 0.
  • ThreatDistance: Near = (8 − 7.5) / 4 = 0.125; Medium = (7.5 − 5) / 5 = 0.5.

So Relay heals before it shoots. The first draft of the rules got this wrong (defend 0.53 against heal 0.35). Tracing it by hand caught the bug, which is a good story to tell in the viva.

Layer 3 · RelayUtility.cs Lecture 03 utility-based agents

Expected utility: choosing the action

Theory. A goal-based agent only knows "goal reached or not". A utility-based agent scores how good each outcome is. When outcomes are uncertain it maximises expected utility: the utility of each outcome weighted by its probability.

EU(a) = P(success | a, state) × U(a) action = argmaxa EU(a)
ActionU(a)P(success)
HealHealUrgency0 on cooldown or player down; 1 in range with line of sight; 0.7 if it must fly there first
DefendDefendUrgency0 with no target or on cooldown; 1 in range; 0.6 if it must reposition
RetreatSelfPreservation1 if a threat was seen recently, else 0
Reposition0.3 × exposure removed + 0.5 × fire-lane blocking removed1 if layer 5 found a spot better by more than 0.1
Follow0.2 + 0.4 × clamp(distance / 9)1 (always possible: the fallback)

A hysteresis bonus of +0.05 goes to last cycle's choice, so Relay doesn't flicker between two nearly equal actions. Ties go to Retreat, then Heal, Defend, Reposition, Follow.

Limitation to admit: the P values (0.7, 0.6) are designer estimates, not learned or computed with Bayes' rule. A stretch goal is a Bayesian belief "P(player in danger | evidence)" from Lecture 09 part 2.

Layer 4 · RelayTacticalGraph.cs + Algorithms/Search Lectures 04–05

Tactical A*: the safest route, not just the shortest

Theory. A search problem has states, actions, step costs and a goal. Uninformed strategies (BFS, DFS, uniform-cost) expand nodes blindly. Informed strategies use a heuristic h(n), an estimate of the remaining cost.

Strategyf(n)Optimal?Note
Uniform-cost (L04)g(n)YesBlind: expands in rings of equal cost
Greedy best-first (L05)h(n)NoFast, but can take a costly route
A* (L05)g(n) + h(n)Yes, if h is admissible (tree) / consistent (graph)Focuses the search towards the goal
  • Admissible: h(n) ≤ h*(n), it never overestimates.
  • Consistent: h(n) ≤ c(n, n′) + h(n′) for every step. Then f never decreases along a path, so A* graph search is optimal.

Relay's search problem

  • States: cells of a 1 m grid sampled on the NavMesh around Relay.
  • Actions: move to one of 8 neighbours if the NavMesh connects them.
  • Step cost: c(n, n′) = |n − n′| + λ · exposure(n′), λ = 3. Exposure is the summed confidence of remembered threats that can see the cell (capped at 1).
  • Heuristic: h(n) = straight-line distance to the goal.
Proof: exposure ≥ 0, so every step costs at least its length.
⇒ the true remaining cost ≥ straight-line distance ⇒ h is admissible.
Triangle inequality: h(n) ≤ |n − n′| + h(n′) ≤ c(n, n′) + h(n′) ⇒ h is consistent ⇒ A* is optimal.

Implementation details worth knowing: a binary-heap priority queue; a closed set (graph search); goal test when a node is popped, not when it is generated (otherwise a costlier path can win); a 2,500-node budget; and replanning when the goal moves more than 1.5 m, after 1 s, or when the set of known threats changes.

Why does λ = 3 expand more nodes than λ = 0? The heuristic is admissible in both cases, but it is far better informed when the cost is close to plain distance. When exposure adds a lot to the cost, h underestimates more, so A* has to explore more. That's still about half of what uniform-cost search needs.

Layer 5 · RelayPositionSearch.cs + Algorithms/Local Lecture 05 local search

Simulated annealing: where to stand

Path versus state. A* answers "how do I get there"; the path matters. "Where should I stand" is different: only the final state matters. That makes it an optimisation problem, which is what local search solves. Local search keeps one current state and moves to neighbours.

  • Hill climbing moves only uphill. It is fast, but it stops at the first local maximum ("climbing Everest in thick fog").
  • Simulated annealing sometimes accepts a worse move, so it can escape local maxima. The chance is high while the temperature T is high, and drops as T cools.
P(accept worse move) = eΔE / T (ΔE < 0) Tk = T0 · αk, T0 = 1, α = 0.85
e.g. ΔE = −1: T = 1 → 0.37, T = 0.1 → e−10 ≈ 0.00005

Relay's objective E(x) (maximised)

For the Support goal (used by Follow and Reposition):

E(x) = 1.0·inBand(1.8–3.5 m from player) + 0.6·seesPlayer + 1.0·(1 − exposure) − 1.5·inPlayersFireLane − 0.15·distance(formation) − 0.05·travel

Heal, Defend and Retreat use the same building blocks with different weights. For example, Retreat values cover and distance from threats most. Neighbours are random points within a radius that shrinks from 3 m to 0.5 m as the search cools, snapped onto the NavMesh. Each search runs 60 iterations (a fixed budget, because the world is dynamic) and is warm-started from the previous best.

Measured results

  • Two-peak test, 100 seeded runs: annealing reached the global peak 38 times; hill climbing 0 times, because it always stops on the first peak.
  • In the lab: with Relay 3 m in front of the player, Reposition was chosen (0.50 against Follow's 0.38). The search accepted 9 worse moves while hot, and the chosen spot is out of the fire lane.

Scope

The other lectures, and why they aren't in Relay

An examiner may ask why a technique wasn't used. Short, defensible answers:

TopicAnswer
BFS / DFS (L04)Uniform-cost search is in the code as the comparison baseline. BFS ignores step costs (exposure), and DFS is neither optimal nor complete in infinite spaces.
Logic, forward chaining (L08)Relay's knowledge is vague and numeric, which suits fuzzy rules better than crisp logic. The reflex layer is a small condition-action rule base.
Bayes' rule (L09 part 2)A planned extension: replace hand-set success chances with P(danger | health drop, threat visible).
Minimax, alpha-beta, expectimax (L10)Relay is not playing a turn-based zero-sum game against the boss. Expectimax could choose a dodge spot against the boss's random attack choice, which is a stretch goal.
CSP (L11)The position choice has soft trade-offs (scores), not hard constraints, so optimisation fits better than satisfaction. Range and line of sight could be modelled as CSP constraints, though.
Genetic algorithms, PSO, ACO (L06)Population methods need many evaluations. Annealing gives a good spot in 60 evaluations inside a 0.2 s decision cycle.
Learning agents (L03)Not needed in a known environment. A possible extension is a critic that tunes the rule weights from evaluation metrics.
Technical defence

Viva questions with model answers

What kind of agent is Relay?

A hybrid, subsumption agent (Lecture 03). A reflex layer overrides a deliberative core that is model-based (it remembers threats), utility-based (expected utility over fuzzy urgencies) and goal-based where it plans routes (A*) and positions (simulated annealing).

Why isn't a simple reflex agent enough?

The environment is partially observable: an enemy behind a wall disappears from the sensors. A reflex agent forgets it instantly. Relay keeps tracks with a transition model (constant velocity) and confidence decay e^(−Δt/1.5).

Fuzzify player health 0.5 for me.

Low is a triangle (0.2, 0.45, 0.7). 0.5 is on the falling side: (0.7 − 0.5) / (0.7 − 0.45) = 0.8. Healthy starts rising at 0.55, so it is 0. Critical ends at 0.3, so it is 0.

Why is AND the minimum?

Zadeh's operator: a conjunction is only as true as its weakest part. OR is the maximum (the most optimistic part), and NOT is 1 − μ.

What does the centre of gravity do, and why aggregate first?

It turns the aggregated fuzzy shape into one number: the balance point, ∫μ(x)·x dx / ∫μ(x) dx. Aggregating with max first means two rules concluding the same term don't count that area twice. The code integrates numerically with the trapezoid rule over 1001 samples, and matches the lecture's 41.22.

Where do the probabilities in expected utility come from?

They are designer estimates: 1 when the action can succeed immediately, 0.7 or 0.6 when Relay must move first, and 0 on cooldown. Admit this. The natural extension is Bayes' rule from Lecture 09.

Prove your A* heuristic is admissible and consistent.

Step cost = length + 3 × exposure, with exposure ≥ 0, so every step costs at least its length. Straight-line distance is never more than the length of any path, so h never overestimates. For consistency: h(n) ≤ |n − n′| + h(n′) by the triangle inequality, and |n − n′| ≤ c(n, n′). So f never decreases along a path, and A* graph search returns an optimal route.

A*, uniform-cost and greedy: what is the difference, and what did you measure?

f = g + h, f = g and f = h. On Romania: A* expanded 5 nodes for the 418 km optimum, uniform-cost expanded 12 for the same route, and greedy found a 450 km route. On the real arena: A* 136 nodes against uniform-cost 279.

Why test the goal when a node is popped, not when it is generated?

When it is generated, a cheaper path to it may still be on the frontier. Testing at pop time guarantees the first goal popped has the lowest f, which is what the optimality proof needs.

Why didn't you just use Unity's NavMesh?

NavMesh finds the shortest path and knows nothing about danger. Relay's own A* puts exposure to threats into the step cost, so it can take a slightly longer route through cover. In the arena sweep: 13.1 m through 9 watched cells instead of 11.7 m through 11. The NavMesh is still used as the map, and for the short hop between waypoints.

Why simulated annealing rather than hill climbing?

The score landscape of positions has local maxima, such as a good spot behind one crate and a better one behind a pillar 3 m away. Hill climbing stops at the first. Annealing accepts worse moves with probability e^(ΔE/T) while hot, so it can cross the dip. Test: global peak 38 of 100 against 0 of 100.

Why a fixed 60 iterations?

The environment is dynamic (Lecture 02): the world changes while Relay thinks, so the decision has a time budget. The whole decision cycle averages about 1.1 ms. The search is warm-started from the last best spot, so quality builds up across cycles.

How do you know your changes didn't break anything?

Twenty unit tests built on lecture examples; a regression harness that records nine scenarios after every step (step 2 was proved to change nothing); and a scripted-fight evaluation comparing the old Relay with the new one over 8 seeds.

What are the limitations?
  • No hazard-zone reflex yet (the boss doesn't publish its slam zones).
  • The success probabilities are hand-set.
  • The open arena has little cover, so exposure rarely changes the route there.
  • The fights aren't perfectly repeatable because of frame timing, which is why the evaluation uses several seeds.
  • The extra intelligence costs about 1.1 ms per decision against microseconds before.
Classify the environment along the 7 dimensions.

Partially observable, multi-agent (cooperative and competitive), stochastic, sequential, dynamic, continuous and known. Each one maps to a design choice in the PEAS section.
