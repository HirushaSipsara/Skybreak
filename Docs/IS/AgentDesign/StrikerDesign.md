## 1. Design Summary

**Striker** is an autonomous security drone stationed within the security wings and maintenance passages of the Aurora Vault. Unlike Bastion's utility-based balancing model, Striker implements a **Goal-Based Reactive Agent Architecture** augmented with **Model-Based Memory** and **Dynamic Replanning**.

Striker provides direct architectural diversity within the Skybreak project:
- **Bastion:** Model-based utility agent using baked NavMesh path lengths to weigh competing tactical trade-offs.
- **Striker:** Goal-based reactive agent operating over a discrete 2D spatial grid, utilizing a custom-engineered **A* informed search** for patrol and intruder pursuit, coupled with an **uninformed Breadth-First Search (BFS)** for tactical area sweeps when visual contact with Arc is lost.

Striker is completely independent of baked NavMesh geometry, allowing it to navigate custom dynamic grids and respond immediately to security doors opening and closing.

## 2. Why These Methods Fit (IS Justification)

| Requirement / Challenge | Implemented Method | Academic / Architectural Justification |
|---|---|---|
| **Distinct Architecture** | Goal-Based Reactive Agent | Avoids redundant utility systems. Striker has an unambiguous goal hierarchy: eliminate intruder > sweep last known zone > patrol route. |
| **Informed Search** | A* with Manhattan Heuristic ($f = g + h$) | Used for long-range navigation (patrol loops and direct pursuit). Guarantees the shortest optimal path across the discrete grid. |
| **Uninformed Search** | Breadth-First Search (BFS) | Used when line of sight is broken. In the absence of heuristic information, BFS systematically explores adjacent hiding spots in concentric rings. |
| **Partial Observability** | Model-Based Memory with Linear Decay | Arc ducks behind walls. Striker stores `lastKnownPosition` and tracks memory confidence: $c = \max(0, 1 - \Delta t / T_{\text{mem}})$. |

| **Self-Preservation** | Reactive Low-HP Alert State | Below 25% HP, Striker transitions to defensive Alert, freezing forward movement, locking orientation to the threat, and maximizing return fire. |

## 3. Search Algorithm Specifications & Mathematical Proofs

### 3.1 Informed Search: A* Algorithm

The pathfinder computes the total evaluation function for node $n$:
$$f(n) = g(n) + h(n)$$

Where:
- $g(n)$: Exact path cost accumulated from the start node to $n$. Cardinal unit cost $c(n, n') = 1.0$.
- $h(n)$: Manhattan distance heuristic to the destination:
  $$h(n) = |\text{goal}_x - n_x| + |\text{goal}_z - n_z|$$

#### Proof of Admissibility (Viva Defense)
A heuristic is admissible if it never overestimates the true cost to reach the goal ($h(n) \le h^*(n)$).  
*Proof:* In a 4-connected grid where only cardinal steps (North, South, East, West) of length 1 are permitted, any valid path between $(x_1, z_1)$ and $(x_2, z_2)$ requires at least $|x_2 - x_1|$ horizontal steps and $|z_2 - z_1|$ vertical steps. Obstacles can only increase this minimum. Therefore, the Manhattan distance represents the strict lower bound on path cost, ensuring $h(n) \le h^*(n)$ across all states.

#### Proof of Consistency / Monotonicity (Viva Defense)
A heuristic is consistent if for every node $n$ and neighbor $n'$ generated by action $a$:
$$h(n) \le c(n, n') + h(n')$$
*Proof:* In a single cardinal step, the Manhattan distance between the agent and goal changes by at most 1 ($|h(n) - h(n')| \le 1$). Given that the step cost $c(n, n') = 1.0$, the triangle inequality holds ($h(n) - h(n') \le 1 = c(n, n')$). Because $h$ is consistent, the first time A* expands a node, the path to it is guaranteed to be optimal; no closed node ever requires re-opening.

### 3.2 Uninformed Search: Breadth-First Search (BFS Area Sweep)

When Arc breaks line of sight behind an obstacle, the target coordinate is no longer observable. Striker enters an **uninformed state**: no heuristic exists to predict which corner Arc chose to hide behind.

A* is inappropriate here because any heuristic would be arbitrary and bias the agent toward an ungrounded guess. Instead, Striker executes **Breadth-First Search (BFS)** using a FIFO queue:
1. Enqueue cell of `lastKnownTargetPosition`.
2. Expand outward level-by-level in concentric Manhattan rings.
3. Collect up to $N = 12$ reachable, unvisited passable neighbor cells within radius $R = 4$.
4. Traverse this sequence as a tactical sweep route.

*Viva explanation:* BFS guarantees exploring shallowest depths first, ensuring the drone inspects immediate adjacent cover before expanding outward.

## 4. State Machine Architecture

```
               +-----------------------------------------+
               |                 PATROL                  |
               | (Loops waypoints via A* grid routing)   |
               +-----------------------------------------+
                    |                                ^
        Target Seen |                   Sweep Done / | Memory Expired
      in FOV & LOS  |                                |
                    v                                |
               +-----------------------------------------+
               |                 PURSUE                  |
               | (A* route to Arc's live position; fires)|
               +-----------------------------------------+
                    |                                ^
         Target LOS |                    Target Seen | Again
           Broken   |                                |
                    v                                |
               +-----------------------------------------+
               |                  SWEEP                  |
               | (BFS area sweep around lastKnownPos)    |
               +-----------------------------------------+
                    \                                /
                     \                              /
            HP <= 25% \                            / HP <= 25%
                       v                          v
                     +-------------------------------+
                     |             ALERT             |
                     | (Freezes, locks facing, fires)|
                     +-------------------------------+
```

### State Transition Matrix

| Current State | Condition / Percept | Next State | Action / Planner Output |
|---|---|---|---|
| **Patrol** | `targetInSight == true` | **Pursue** | Computes A* path to Arc; accelerates to `pursueSpeed` (4.8 m/s). |
| **Patrol** | `HealthFraction <= 0.25` | **Alert** | Halts locomotion; locks aim toward last damage source. |
| **Pursue** | `targetInSight == false` | **Sweep** | Generates BFS sweep cells around `lastKnownPosition`; follows search pattern. |
| **Pursue** | `targetInSight && dist <= attackRange` | **Pursue** | Continues tracking; fires hitscan weapon (12 dmg / 1.0s cooldown). |
| **Pursue** | `HealthFraction <= 0.25` | **Alert** | Stops forward charge; readies defensive return fire. |
| **Sweep** | `targetInSight == true` | **Pursue** | Aborts sweep immediately; re-engages direct pursuit via A*. |
| **Sweep** | `MemoryConfidence <= 0` or sweep route finished | **Patrol** | Accepts target escaped; returns to nearest patrol waypoint. |
| **Alert** | `HealthFraction > 0.25` (healed / reset) | **Patrol** | Resumes standard security route. |

## 5. Memory Model & Telemetry

### Memory Confidence Formula
$$\text{Confidence}(t) = \text{clamp01}\left(1.0 - \frac{t - t_{\text{lastSeen}}}{T_{\text{memory}}}\right)$$
- While Arc is visible: Confidence $= 1.0$ (100%).
- Upon losing visual contact: Decays linearly over $T_{\text{memory}} = 5.0$ seconds.
- When Confidence reaches $0$: Striker terminates the sweep search and resumes patrol.

### Real-Time GUI Overlay
Striker features an integrated telemetry HUD displaying:
- Current State (`Patrol`, `Pursue`, `Sweep`, `Alert`) with color coding.
- Striker Health % & Alert Threshold.
- Line of sight status (CLEAR / BLOCKED) and direct distance.
- Memory Confidence gauge (%).
- Remaining path nodes in current plan.
- Navigation Grid Topology Version.

## 6. Integration With Door Physics & Combat

### Dynamic Door Replanning
- Security doors implement `SlidingSecurityDoor` (kinematic leaf, anti-crush volume, state machine).
- When a door opens or closes, `StrikerGrid.NotifyWorldChanged()` or `SetAreaPassable()` updates the affected cells and increments `StrikerGrid.Version`.
- In `StrikerAgent.Update()`, Striker checks `if (grid.Version != cachedGridVersion)`. If a mismatch is detected, the agent immediately recalculates its current A* or BFS route, smoothly adapting without clipping or waiting for frame timeouts.

### Combat Protocol
- **Player -> Striker:** Arc fires using `ArcController.Fire()`. Raycasts hitting Striker's collider call `IDamageable.ApplyDamage()`. Striker's `CombatHealth` records the hit, turns toward the attacker, and enters `Pursue` even if Arc was behind the drone.
- **Striker -> Player:** Striker uses strict line-of-sight raycasts from `muzzlePoint`. Shots cannot pass through walls or closed security doors. When line of sight is clear, applies 12 damage via `IDamageable.ApplyDamage()`.

## 8. Viva Presentation Script (Quick Reference)

- **Q: Why didn't you use utility theory like Bastion?**  
  *"Bastion is a heavy turret/bunker agent that balances ambiguous trade-offs like holding cover versus retreating. Striker is an agile patrol drone with a strict goal hierarchy: intruder interception overrides area search, which overrides routine patrol. Goal-based architecture represents this clean hierarchy without inventing arbitrary competing weight curves."*

- **Q: Explain your A* heuristic.**  
  *"I use the Manhattan distance: $h(n) = |\Delta x| + |\Delta z|$. Because our grid uses cardinal 4-direction movement with unit step cost 1, the Manhattan distance is mathematically admissible (it never overestimates the true distance) and monotonic/consistent ($h(n) \le c(n, n') + h(n')$). This guarantees optimal paths and eliminates the need to re-open nodes in the closed set."*

- **Q: Why use BFS for the search instead of A*?**  
  *"A* requires a known goal coordinate to evaluate $h(n)$. When Arc breaks line of sight behind a barrier, the agent has no information about which direction Arc fled. BFS is an uninformed search: it expands in uniform concentric rings, ensuring the drone thoroughly searches immediate hiding spots before checking deeper ones."*
